# Data Model: Property Onboarding

**Feature**: [spec.md](spec.md) · **Plan**: [plan.md](plan.md) · **Decisions**: [research.md](research.md)

Conventions (same as feature 001):

- IDs are UUIDs generated by the database.
- Timestamps are `timestamptz` in UTC. Calendar dates are `date`, and times of day are `time`
  without a time zone; both are read in the property's `time_zone` (FR-005).
- **Every table in this feature is tenant-owned:** it carries `workspace_id`, RLS is enabled and
  forced, and the RLS migration check covers it (SEC-14).
- **Write access** follows the `properties.manage` and `integrations.manage` capabilities of spec
  001 (owner and admin). Agents only read, and never read restricted columns (FR-046).
- **Restricted columns** (`*_ciphertext`) hold AES-256-GCM ciphertext under a per-workspace data
  key ([research R5](research.md#r5-field-level-encryption-sec-06)). They are excluded from every
  API response and log line, and the `guidesk_app` role cannot select them in agent-facing views.
- **Confidential columns** (guest names) are scrubbed from logs and follow the retention job in
  §6.

## 1. Properties

### `property`

| Field | Type | Rules |
|---|---|---|
| `id` | uuid, PK | — |
| `workspace_id` | uuid, FK → workspace (`ON DELETE CASCADE`) | — |
| `name` | text, 1–120 characters | Required (FR-001). Not unique; duplicates are allowed |
| `address_line1` | text, 1–200, nullable | Required for `ready` (FR-001) |
| `address_unit`, `region`, `postal_code` | text, nullable | Optional (edge case: addresses without postal codes) |
| `city` | text, 1–120, nullable | Required for `ready` |
| `country` | char(2), nullable | ISO 3166-1 alpha-2; required for `ready` |
| `address_key` | text, nullable | Normalized `line1 + unit + city + country` for the duplicate-address warning (FR-007). Not unique |
| `time_zone` | text, nullable | IANA zone, validated against the runtime's zone list; required for `ready` (FR-002) |
| `check_in_time`, `checkout_time` | time, nullable | Required for `ready` |
| `max_guests` | smallint 1–50, nullable | Required for `ready` |
| `guide_languages` | text[] of `es`, `en` | At least one; defaults to the workspace language first (FR-003) |
| `setup_status` | enum `needs_details`, `to_confirm`, `ready` | `needs_details`: required facts missing. `to_confirm`: every fact present but not yet confirmed by the host (CSV and PMS imports). `ready`: confirmed with every required fact (FR-004). Spec 003 adds `published` |
| `missing_facts` | text[] | Names of the required facts still missing; empty when `ready` |
| `edited_facts` | text[] | Facts the host changed after an import; re-import never overwrites them (FR-033) |
| `source` | enum `manual`, `listing_text`, `csv`, `pms`, `duplicate` | Set at creation, never changed (FR-006) |
| `source_provider` | enum `beds24`, `hostex`, nullable | Set when `source = pms`; kept after disconnect (FR-036) |
| `pms_connection_id` | uuid, nullable, FK → pms_connection (`ON DELETE SET NULL`) | Cleared on disconnect |
| `external_id` | text, nullable | The PMS listing ID: `{propertyId}:{roomTypeId}` for Beds24, the property ID for Hostex ([research R7](research.md#r7-pms-adapters-beds24-and-hostex)). Partial unique index on `(workspace_id, source_provider, external_id)` (FR-033) |
| `pms_status` | enum `linked`, `not_found`, nullable | `not_found` when the listing disappears from the PMS (edge case) |
| `duplicated_from_id` | uuid, nullable, FK → property (`ON DELETE SET NULL`) | History only |
| `status` | enum `active`, `removed` | — |
| `removed_at`, `removed_by`, `purge_after` | nullable | `purge_after` = `removed_at` + 30 days (FR-045) |
| `created_by` | text, nullable, FK → user (`ON DELETE SET NULL`) | — |
| `created_at`, `updated_at` | timestamptz | — |

**Rules:**

- **Plan limit (FR-047):** a creation path locks the workspace row (`SELECT … FOR UPDATE`),
  counts `active` properties, and compares with `workspace.property_limit` (below). Concurrent
  creations can never exceed the limit. `removed` properties do not count.
- **MFA threshold (FR-048):** the `PropertyCountProvider` from spec 001 now counts `active`
  properties, so `requiresMfa` applies at 3.
- **Pending deletion (FR-049):** inserts are refused while `workspace.status = pending_deletion`
  (checked in the same transaction, and by an RLS `WITH CHECK`).

**RLS:** members of the workspace read `active` rows; owners and admins also read `removed` rows
(restore). Inserts and updates need `properties.manage`.

UTC day in `rate_limit_bucket` (feature 001). Refused requests make no AI call (AC-SEC-010). A
URL-only input does not count; a retry counts like a new request.

## 3. Calendar feeds and stays

### `calendar_feed`

| Field | Type | Rules |
|---|---|---|
| `id` | uuid, PK | — |
| `workspace_id`, `property_id` | uuid, FK (`ON DELETE CASCADE`) | At most 5 per property (FR-020), enforced by a trigger |
| `channel` | enum `airbnb`, `booking`, `vrbo`, `other` | Detected from the link's host; the host can change it. One feed per channel (FR-020): partial unique index on `(property_id, channel)` where `channel <> 'other'` |
| `channel_label` | text, ≤ 40, nullable | Required when `channel = other` (check constraint). Partial unique index on `(property_id, channel_label)` where `channel = 'other'` |
| `url_ciphertext` | bytea | Restricted (FR-025) |
| `url_fingerprint` | text | HMAC-SHA-256 of the normalized URL with a server secret. Unique per property, to reject the same link twice without decrypting |
| `display_hint` | text | Masked form shown after saving, for example `airbnb.com/…/a1b2.ics` |
| `data_key_id` | uuid, FK → workspace_data_key | — |
| `status` | enum `active`, `failing` | `failing` after the first failed read |
| `last_success_at`, `last_attempt_at`, `failing_since`, `alerted_at` | timestamptz, nullable | Alert once after 24 hours of failures (FR-024) |
| `last_error_code` | text, nullable | For example `not_https`, `blocked_address`, `too_large`, `timeout`, `http_404`, `not_ical` |
| `etag`, `last_modified` | text, nullable | Conditional requests |
| `manual_refresh_at` | timestamptz, nullable | "Refresh now" at most once every 5 minutes per property (FR-023) |
| `created_by`, `created_at`, `updated_at` | — | — |

**RLS:** owners and admins read rows. Every member, agents included, reads through the
`calendar_feed_public` view, which omits `url_ciphertext`, `url_fingerprint`, and `display_hint`
(FR-025, US3 scenario 6). The view runs with its owner's rights, so the table's policies do not
apply to it: it filters itself with `workspace_id = current_setting('app.workspace_id')::uuid`
and `app_current_workspace_role() IS NOT NULL`, and returns nothing without a workspace context.

### `stay`

| Field | Type | Rules |
|---|---|---|
| `id` | uuid, PK | — |
| `workspace_id`, `property_id` | uuid, FK (`ON DELETE CASCADE`) | — |
| `source` | enum `ical`, `pms`, `manual` | — |
| `calendar_feed_id` | uuid, nullable, FK (`ON DELETE CASCADE`) | Unique with `external_uid` |
| `pms_connection_id` | uuid, nullable, FK (`ON DELETE SET NULL`) | Unique with `external_uid` while set |
| `external_uid` | text, nullable | iCal `UID` or PMS booking ID |
| `check_in_date`, `checkout_date` | date | `checkout_date` > `check_in_date` |
| `check_in_time`, `checkout_time` | time, nullable | Null uses the property's times; set only for manual stays (FR-052) |
| `channel` | text, ≤ 40 | `Airbnb`, `Booking.com`, `Direct`, and so on |
| `status` | enum `active`, `cancelled`, `hidden` | "Upcoming" in the spec = `active` with `checkout_date` ≥ today in the property's time zone |
| `may_be_block` | boolean | Unlabeled feed entry (FR-022) |
| `guest_count` | smallint, nullable | PMS or manual only |
| `guest_name` | text, ≤ 120, nullable | Confidential. PMS or manual only (FR-030, FR-052) |
| `guest_name_removed_at` | timestamptz, nullable | Set when an owner or admin removes the guest name on request; refreshes never write `guest_name` again while it is set (FR-053) |
| `booking_reference` | text, ≤ 80, nullable | PMS only |
| `duplicate_of_id` | uuid, nullable, FK → stay | Set when the same reservation arrives from another source; hidden from lists (edge cases) |
| `overlaps` | boolean | Overlap with another visible stay (iCal edge case, FR-054) |
| `last_seen_at` | timestamptz, nullable | Last refresh that returned it; used to mark `cancelled` (FR-023, FR-035) |
| `created_by` | text, nullable | Manual stays only |
| `created_at`, `updated_at`, `cancelled_at` | timestamptz | — |

**Rules:**

- Only `manual` stays are editable (FR-053). Feed and PMS stays allow two changes from a member:
  `active` → `hidden` when `may_be_block` is true, and removing the guest name (`guest_name` set
  to null, `guest_name_removed_at` set). A hidden row keeps its `external_uid`, so later
  refreshes leave it hidden.
- Refreshes never touch `manual` stays (FR-053), and never restore a removed guest name.
- **Deduplication** (edge cases): a PMS stay wins over a feed stay with the same property and
  dates; an unlabeled feed entry whose dates match a labeled reservation from another feed is
  marked `duplicate_of_id`.
- Stays with `checkout_date` before today are not created by refreshes (FR-022).

**RLS:** members read rows, including agents (FR-046). Writes need `properties.manage` and are
limited to `manual` rows, or to the hide and guest-name-removal changes. The trigger that limits
feed and PMS rows applies only to the request role (`current_user = 'guidesk_app'`); the system
context that refreshes run in updates and cancels feed and PMS stays.

## 6. Retention and deletion

| Data | Rule | Job |
|---|---|---|
| Screenshots and CSV files | Deleted after processing; bucket lifecycle deletes anything older than 1 day | Worker, plus S3 lifecycle |
| `extraction_request.input_text`, `recognized_text` | Deleted when the property is confirmed, or 7 days after the request | Daily `retention` job |
| `stay.guest_name` | Set to null 12 months after `checkout_date` (Confidential class; to be confirmed by OQ-35), or at once when an owner or admin removes it on request (FR-053) | Daily `retention` job; API for removal on request |
| `import_item.calendar_url_ciphertext` | Set to null once the feed is saved or rejected, and when the run is cancelled | Worker (`csv.import`) and API (cancel); the daily `retention` job clears any left on finished runs |
| `import_item.row_values` | Set to null 7 days after the run finishes; the error file is no longer available after that | Daily `retention` job |
| CSV runs in `awaiting_confirmation` | Cancelled after 7 days, which clears their items as above | Daily `retention` job |
| Removed properties | Deleted with their stays, listing content, feeds, and restricted values when `purge_after` passes (FR-045) | Daily `purge-properties` job |
| `pms_connection.credential_ciphertext` | Set to null at once on disconnect | API, in the disconnect transaction |

## 7. State machines

### Property

```text
blank, listing text, duplicate: confirmation step with every fact ──> ready
CSV or PMS import: facts incomplete ──> needs_details ──(host fills them)──> to_confirm
                   facts complete   ──> to_confirm ──(host confirms, one or many)──> ready
ready ──(a required fact cleared)──> needs_details
manual, listing text, duplicate: needs_details ──(host fills them)──> ready
```

A `PATCH` that fills the last missing fact makes a manual, listing-text, or duplicate property
`ready`, because the host is editing it directly, and a CSV or PMS property `to_confirm`, because
its other facts still come from the import.

```text
active ──(remove: typed name + step-up)──> removed ──(restore within 30 days, free slot)──> active
removed ──(purge_after passes)──> deleted permanently
```

### Extraction request

```text
awaiting_uploads ──(submit)──> queued ──> running ──> succeeded
                                                  └─> failed (timeout, ai_unavailable, nothing_found)
url_only input ──> failed (url_only) with no AI call
failed (timeout, ai_unavailable) ──(retry)──> a new request, queued, with retry_of_id set
```

### Import run

```text
CSV: validating ──> awaiting_confirmation ──(create valid rows)──> running ──> completed
                                          └─(cancel, or 7 days without confirmation)──> cancelled
PMS: running ──> completed (with per-item outcomes) | failed (credential revoked: remaining items failed)
```

### Calendar feed and PMS connection

```text
active ──(read fails)──> failing ──(24 h)──> failing + alerted ──(read succeeds)──> active
PMS connection: active ⇄ failing ──(disconnect)──> disconnected (credential deleted)
```

## 8. Validation rules mapped to requirements

| Rule | Requirement |
|---|---|
| Required facts: name, street line, city, country, time zone, check-in, checkout, max guests, ≥ 1 language | FR-001, FR-004 |
| Time zone suggested from country and city, without an outside service | FR-002 |
| Same normalized address in the workspace shows a dismissible warning | FR-007 |
| Pasted text ≤ 20,000 characters; ≤ 10 screenshots of ≤ 10 MB each | FR-009 |
| Likely restricted values removed before any AI call; images never sent to the AI | FR-012, FR-013 |
| Extraction limit = max(10, 2 × property limit) per workspace per UTC day | FR-017 |
| ≤ 5 feeds per property, one per channel (several `other` feeds with distinct labels), HTTPS only, at most 3 redirects, 2 MB and 10 s per read | FR-020, FR-026 |
| Feed refresh every 3 hours; "Refresh now" once every 5 minutes per property | FR-023 |
| PMS stays keep only dates, channel, reference, guest count, and guest name | FR-030 |
| Re-import matches by `external_id`; `edited` facts and reviewed content are never overwritten | FR-033 |
| CSV: UTF-8 with or without BOM, comma or semicolon, ≤ 500 rows and 2 MB | FR-038 |
| Downloads prefix formula-leading cells (`=`, `+`, `-`, `@`, tab, carriage return) with `'` | FR-041 |
| Active properties ≤ `property_limit` (default 2) | FR-047 |
| Manual stays: checkout after check-in; overlap shows a warning | FR-052, FR-054 |
